## 1. 背景與問題

課堂上老師發下 Guided Notes（學習單），各組填寫後，傳統做法是請學生上台在黑板寫答案搶答，耗時且難以判斷誰先。本系統把搶答搬到線上：

1. 老師匯入 Google Sheets 版 Guided Notes，系統自動辨識題號與題組。
2. 老師開放搶答，各組以瀏覽器線上送出答案。
3. 系統依伺服器收到的時間判定得主（可選公平模式）。
4. 老師結束搶答後，系統把得主答案寫回原 Guided Notes。

## 2. 目標與成功指標

| 目標 | 指標 |
| --- | --- |
| 題目匯入免手動 | 兩份範例範本皆 100% 正確辨識題號、題組、作答格，且不修改程式 |
| 判定公平可驗證 | 同一題 50 次並行送出測試，每次恰好 1 位得主 |
| 資訊隔離 | 搶答結束前，任一學生端（畫面與 WebSocket 封包）收不到他組任何資訊 |
| 即時同步 | 本機環境下，老師按開始／結束後 1 秒內所有分頁切換；送出到老師畫面更新 < 500 ms |
| 結果回寫 | 匯出後每個得主答案出現在原檔正確的作答格，其他儲存格不變 |

## 3. 範圍

### 3.1 範圍內

- 核心功能 FR-01～FR-12（第 6 節）。
- 額外功能 E1 題組、E2 CSV、E3 公平機制、E4 撤回、E5 人工判錯、E7 斷線重連（第 7 節）。
- 本機執行（`localhost`），以多個瀏覽器分頁模擬多組。

### 3.2 範圍外（Non-goals）

- 對外部署、HTTPS、帳號註冊與密碼系統、學號驗證。
- 自動批改答案對錯（由老師判讀，E5 提供人工判錯）。
- 匯入題目敘述文字（只以題號表示）。
- E6 計分板／倒數計時介面、E8 活動回放。
- 多位老師同時管理同一活動。

## 4. 角色

| 角色 | 說明 | 身分識別 |
| --- | --- | --- |
| 老師（Teacher） | 主導活動的唯一管理者 | 輸入 `.env` 中的 `TEACHER_PASSWORD` 登入 |
| 學生／組員（Member） | 以「組」為單位作答；一組可有多位組員 | 房間碼 + 選擇組別 + 暱稱；伺服器發給 member token，存在瀏覽器 localStorage |
| 組（Team） | 搶答與計分的單位 | 由老師設定組數，系統建立「第 1 組」…「第 N 組」 |

## 5. 使用者流程（高階）

### 5.1 老師

1. 開啟 `/teacher`，輸入管理密碼登入。
2. 建立活動 → 取得 6 碼房間碼，設定組數（預設 6）與判定模式（純速度／公平模式，視窗秒數預設 3）。
3. 貼上 Google Sheets 網址匯入 → 檢視「偵測到 N 題，其中 M 題組」摘要與題目清單 → 確認。
4. 把房間碼告訴學生，看各組加入人數。
5. 按「開始搶答」→ 即時看到每題每組的送出狀態、答案、送出者、時間、順位、得主。
6. 必要時對某題「判錯」，系統遞補下一順位。
7. 按「結束搶答」→ 所有人看到結果。
8. 按「寫回 Google Sheets」與「下載 CSV」；必要時「還原原始內容」。
9. 可按「重新開始一輪」回到等待開始狀態（清除送出紀錄，保留題目與組別）。

### 5.2 學生

1. 開啟 `/join`，輸入房間碼、選組別、填暱稱 → 進入 `/play`。
2. 等待開始時看到題號清單（輸入框鎖定）。
3. 搶答中，與組員共同編輯組內草稿（即時同步），任一人按「送出」代表全組送出該題。
4. 送出後 10 秒內可「撤回」並重新送出；搶答中只看得到本組「已送出」，看不到是否得主或順位。
5. 搶答結束後看到每題得主、答案與各組順位。
6. 重新整理頁面或斷線後自動回到原組別、原狀態。

## 6. 核心功能需求（MUST）

| ID | 需求 | 驗收重點 |
| --- | --- | --- |
| FR-01 | 老師能匯入 Google Sheets 版 Guided Notes，系統依範本結構自動辨識題號；題數必須與原檔一致 | 範例 A＝4 題、範例 B＝6 題 |
| FR-02 | 題目只以題號表示，不匯入、不顯示題目敘述 | UI 只出現「第 n 題」 |
| FR-03 | 老師能開始搶答、結束搶答 | 階段 READY→RUNNING→ENDED |
| FR-04 | 老師能在搶答中即時檢視各題各組作答狀況 | 送出後 < 500 ms 出現在老師畫面 |
| FR-05 | 老師能檢視搶答結果：每題得主、答案、所有組順位 | ENDED 後可見 |
| FR-06 | 老師能把得主答案寫回原 Guided Notes 對應作答格；寫入位置必須動態定位，禁止寫死儲存格 | 換範本不改程式 |
| FR-07 | 學生只能在搶答中作答與送出；其他階段輸入鎖定，伺服器也拒絕 | 直接打 API 回 409 |
| FR-08 | 學生以組為單位送出；同組任一成員送出即代表全組，每組每題只採計一份有效答案 | 同組同時送出只存 1 筆 |
| FR-09 | 學生在搶答結束後能檢視結果 | ENDED 後可見 |
| FR-10 | 搶答結束前，學生看不到其他組的任何作答狀況、答案、順位或「是否已有人送出」；必須由伺服器過濾，不能只靠前端隱藏 | WebSocket 封包檢查 |
| FR-11 | 以伺服器收到請求的時間判定最快者為搶答成功（公平模式見 E3）；同一題恰好一位得主 | 並行測試 |
| FR-12 | 所有使用者的活動階段即時同步 | 1 秒內切換 |

## 7. 額外功能需求（本專案範圍內，MUST）

| ID | 功能 | 規則 |
| --- | --- | --- |
| E1 | 題組 | 題號儲存格縱向合併 n 列＝含 n 子題的題組；題組必須一次送出所有子題，任一子題空白則拒絕；題組共用一個時間戳、一個順位，得主得 1 分 |
| E2 | 匯出 CSV | 每個送出的每個子題一列；UTF-8 BOM、CRLF；欄位見 TECH_SPEC §7.5 |
| E3 | 公平機制：緩衝視窗 + 低分優先 | 某題第一筆送出開啟 W 秒視窗（預設 3，老師可設 1–10；設定為「純速度」時 W＝0 立即判定）；視窗結束時，視窗內送出者依「目前得分少者優先 → 同分則較早送出者優先」排序，第一名為得主 |
| E4 | 撤回 | 送出後 10 秒內可撤回（不論是否為得主，避免撤回按鈕洩漏得主資訊）；撤回的若是得主，依既有順位遞補下一個有效送出；撤回後可重新送出，以新送出時間計算並排在已結算名次之後 |
| E5 | 老師人工判錯 | 老師可把某題得主標為錯誤：原得主扣 1 分，依既有順位遞補下一個有效送出為得主並加 1 分；無人可遞補則該題無得主；匯出以最終得主為準 |
| E7 | 斷線重連 | 學生重新整理或斷線後，以 localStorage token 自動回到原組別、草稿與送出狀態；老師以 sessionStorage token 回到管理頁 |

## 8. 業務規則

1. **伺服器為唯一真相來源**：階段、時間、得主、分數一律由伺服器決定，客戶端時間不採用。
2. **時間戳**：伺服器在處理送出請求時取得 `serverTime`（毫秒）與遞增序號 `seq`；排序一律 `serverTime` 再 `seq`。
3. **唯一性**：每組每題最多 1 筆 `active` 或 `rejected` 送出；`withdrawn` 不佔名額。
4. **得主之後的送出**：得主決定後其他組仍可送出，依時間排在後面，作為 E5 遞補候選。
5. **結束時未結算的視窗**：老師按「結束搶答」時立即結算所有視窗中的題目，再進入 ENDED。
6. **計分**：每題（含題組）得主 +1；判錯 −1；分數用於 E3 排序與結果顯示。
7. **答案格式**：每個子題答案去除前後空白後必須 1–200 字元。
8. **暱稱**：去除前後空白後 1–20 字元；同組內不可重複（不分大小寫）。
9. **寫回格式**：作答格原本若有子題前綴（如「（1）」），寫回值＝前綴＋答案；否則＝答案。只寫有得主的題目。
10. **寫回前快照**：匯入時保存每個作答格原始值，提供「還原原始內容」。

## 9. Guided Notes 範本格式（匯入前提）

依兩份範例（`fixtures/sheets/template-a.xlsx`、`template-b.xlsx`）歸納：

- 任一工作表中，同一列同時有文字「題號」與「作答」的儲存格＝表頭列；兩者所在欄＝題號欄、作答欄（合併儲存格取左上角）。
- 表頭列以下，題號欄內容為整數（容許 `1`、`1.0`、前後空白）的列＝一題的起點。
- 題號格若縱向合併 n 列（n>1）＝題組，子題為這 n 列；否則為單題。
- 子題編號取作答格開頭的「（n）」或「(n)」，沒有則依列序 1..n。
- 題號欄為空白的列（含間隔列、合併空白列）忽略。

助教用其他 Guided Notes 測試時，只要保留上述「題號／作答」表頭結構即可，README 必須寫明。

## 10. 非功能需求

| 類別 | 需求 |
| --- | --- |
| 效能 | 支援 10 組 × 4 人＝40 個分頁同時連線；送出到老師畫面更新 < 500 ms（本機） |
| 正確性 | 並行送出不會產生兩位得主；伺服器重啟後恢復活動狀態與未結算視窗 |
| 安全 | 管理密碼、Google 金鑰只放 `.env`／`secrets/`，不進 repo；repo 附 `.env.example` |
| 可攜性 | `npm install` 後 `npm run dev` 一鍵啟動；不設定 Google 金鑰時可用 fake 模式以 fixture 示範 |
| 可測性 | 每個功能都有 unit test；domain、sheets、export 模組行覆蓋率 ≥ 95%，全專案 ≥ 80%（細節見 TEST_SPEC §2.3） |
| 一致性 | 程式、spec、PlantUML 圖、Demo 影片描述必須一致 |

## 12. 名詞

| 名詞 | 定義 |
| --- | --- |
| 活動（Session） | 一次搶答，擁有房間碼、題目、組別、階段 |
| 題目（Question） | 一個題號；可能是單題或題組 |
| 作答格（AnswerSlot） | 題目在試算表中要寫回答案的儲存格；單題 1 格、題組 n 格 |
| 送出（Submission） | 某組對某題的一次送出 |
| 視窗（Window） | 公平模式下，第一筆送出後等待其他組的秒數 |
| 結算（Settle） | 決定某題得主與順位的動作 |
