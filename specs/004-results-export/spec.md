## 名詞與階段對照

| 名詞 | 說明 |
| --- | --- |
| 等待開始 | 題目已匯入、尚未開始搶答；本子功能只允許「還原原始內容」 |
| 搶答中 | 老師可判錯；不可寫回、不可下載 CSV |
| 已結束 | 老師與學生看到結果；老師可判錯、寫回、還原、下載 CSV |
| 送出狀態 | 「有效」「已撤回」「判錯」三種（003 產生前兩種，本子功能產生「判錯」） |
| 順位 | 某題所有未撤回送出（含判錯）的排序位置，1 起算、連續不重複；沿用 003 的排序規則 |
| 得主 | 某題順位最前、狀態為「有效」且已結算的送出所屬組；每題最多 1 位；判錯的送出保留順位但不能是得主 |
| 判錯 | 老師把某題目前得主的送出標為錯誤；不可復原 |
| 遞補 | 原得主被判錯後，依既有順位由下一個「有效」且已結算的送出成為得主 |
| 分數 | 某組目前是得主的題數（判錯後自動少 1、遞補者自動多 1；不會小於 0） |
| 作答格 | 002 匯入時記錄的、每題要寫回答案的儲存格；單題 1 格、題組每子題 1 格；含位置、子題前綴與匯入時原始值 |
| 子題前綴 | 作答格原始內容開頭的子題編號文字，例如「（1）」「(2)」；沒有則為空 |
| 寫回 | 把每題最終得主的答案寫入原 Guided Notes 對應作答格 |
| 還原原始內容 | 把所有作答格恢復成匯入時的原始值 |
| 第幾輪 | 活動的輪次，從 1 開始，每次「重新開始一輪」加 1（003） |

## Clarifications

### Session 2026-11-24

- Q: 某題已寫回過，之後被判錯到沒有得主，再按寫回時該題作答格要怎麼處理？ → A: 寫回時把該題作答格恢復為匯入時的原始值，並計入「已寫回 N 格」。判定方式為「目前沒有得主、且有被判錯的送出」的題目（不需記錄是否寫回過，結果可重現）；從未有人被判錯的無得主題目仍不寫。（與 TECH_SPEC §7.4「無得主的題目不產生寫入」不同，依憲章原則 II 需在 plan 階段提出差異並同步 docs。）
- Q: 搶答結束後，學生結果畫面是否也顯示各組分數？ → A: 是；學生看到與老師相同的內容（每題得主、答案、各組順位，以及所有組的分數），只是沒有判錯等操作按鈕。
- Q: 「還原原始內容」完成後老師畫面顯示什麼文字？ → A: 「已還原 N 格」，N 為本次寫入的作答格總數（範例 A 為 6），顯示位置與「已寫回 N 格」相同。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 搶答結束後老師與學生看到結果（Priority: P1）

老師按「結束搶答」後，老師畫面顯示結果表：每題一列，列出題號、得主組別、得主答案（題組以子題標籤串接，例如「（1）CPU（2）作業系統」）、各組順位（「1.第 2 組 2.第 1 組」，含被判錯的送出並標示為判錯，不含已撤回的送出），沒有得主的題目在得主與答案欄顯示「無」；表格下方顯示各組分數，依分數由高到低、同分依組別順序（第 1 組在前）排列。學生畫面在同一時間由作答卡切換為相同內容的結果畫面（不含判錯按鈕）。搶答結束前學生看不到任何結果（003 已保證）。

**Why this priority**：看到結果是搶答的收尾（FR-05、FR-09），也是判錯、寫回與 CSV 的基礎；沒有結果畫面，其他故事都無從操作或驗證。

**Independent Test**：以示範模式匯入範例 A，3 組各送出第 1、3 題後結束搶答，檢查老師結果表與學生結果畫面內容一致且正確，不需要判錯、寫回或 CSV。

**Acceptance Scenarios**：

1. **Given** 搶答中第 1 題（題組）第 2 組為得主、第 1 組順位 2，第 3 題第 1 組為得主、第 2 組順位 2，第 2、4 題無人送出，**When** 老師按「結束搶答」，**Then** 老師結果表第 1 題得主為「第 2 組」、答案「（1）CPU（2）作業系統」、順位「1.第 2 組 2.第 1 組」；第 3 題得主「第 1 組」；第 2、4 題得主與答案顯示「無」、順位為空；分數依序為第 1 組 1、第 2 組 1、第 3 組 0……（同分依組別順序，第 1 組排在第 2 組之前）。
2. **Given** 同上情境，**When** 結束搶答，**Then** 每位已連線學生的畫面在 1 秒內隱藏作答卡、顯示與老師相同的每題得主、答案、各組順位與各組分數。
3. **Given** 某題第 3 組送出後撤回且未重送，**When** 結果顯示，**Then** 該題的順位不含第 3 組。
4. **Given** 某題的原得主已被判錯，**When** 結果顯示，**Then** 該組仍出現在該題順位中並標示「判錯」，得主為遞補者。
5. **Given** 搶答中，**When** 學生查看畫面或其收到的資料，**Then** 不含任何結果（得主、順位、分數）。
6. **Given** 已結束，**When** 學生重新整理頁面或新加入的學生進入，**Then** 直接看到結果畫面。

### User Story 2 - 老師判錯與遞補（Priority: P1）

老師判讀答案後，可在搶答中或結束後於結果表（搶答中顯示在即時狀態表下方）對某題按「判錯」：原得主的送出變為「判錯」，該組分數少 1；系統依既有順位找下一個有效送出作為新得主，該組分數多 1。可對同一題連續判錯，直到沒有可遞補者，此時該題沒有得主；再按判錯時提示「此題目前沒有得主」。被判錯的組不能再送出該題，該組學生在作答卡看到「老師判定此答案錯誤」。判錯後老師與學生畫面即時更新。

**Why this priority**：系統不自動批改（PRD §3.2），判錯是讓得主與分數「正確」的唯一手段（E5），且直接決定寫回與 CSV 的內容。

**Independent Test**：結束搶答後，在第 3 題（第 1 組得主、第 2 組順位 2、第 3 組順位 3）連按三次判錯，檢查每次得主、分數與畫面變化，以及第三次後的提示訊息。

**Acceptance Scenarios**：

1. **Given** 已結束，第 3 題 A 組（第 1 組）為得主、B 組（第 2 組）順位 2，**When** 老師按第 3 題「判錯」，**Then** A 組送出標為「判錯」（仍保留順位 1），B 組成為得主，A 組分數 −1、B 組分數 +1；老師結果表與所有學生結果畫面在 1 秒內更新。
2. **Given** 上一情境後第 3 題還有第 3 組順位 3，**When** 老師再按第 3 題「判錯」，**Then** B 組也標為「判錯」，第 3 組成為得主並 +1、B 組 −1。
3. **Given** 第 3 題所有未撤回送出都已被判錯，**When** 老師按第 3 題「判錯」，**Then** 系統提示「此題目前沒有得主」，資料不變；結果表第 3 題得主顯示「無」。
4. **Given** 某題沒有任何送出，**When** 老師按該題「判錯」，**Then** 提示「此題目前沒有得主」。
5. **Given** 活動為「等待開始」（或尚未匯入），**When** 老師（或直接呼叫伺服器）要求判錯，**Then** 系統拒絕並顯示「目前階段不能執行此動作」，資料不變。
6. **Given** 搶答中第 3 題第 1 組為得主，**When** 老師按第 3 題「判錯」，**Then** 第 1 組的作答卡顯示「老師判定此答案錯誤」、輸入鎖定且無送出按鈕；第 1 組再送出第 3 題被拒絕並顯示「本組已送出此題」。
7. **Given** 搶答中第 3 題第 1 組被判錯、第 2 組遞補為得主，**When** 檢查第 2 組及其他組學生收到的畫面與資料，**Then** 都看不到第 1 組被判錯、看不到自己成為得主或任何順位與分數（資訊隔離仍成立，結束後才看到）。
8. **Given** 公平模式、搶答中第 4 題仍在視窗中（尚未結算、尚無得主），**When** 老師按第 4 題「判錯」，**Then** 提示「此題目前沒有得主」，視窗照常結算。
9. **Given** 搶答中判錯使第 1 組分數下降，**When** 之後另一題的公平模式視窗結算，**Then** 以判錯後的分數排序候選。
10. **Given** 已結束且第 3 題 A 組被判錯、B 組遞補，**When** 老師寫回，**Then** 第 3 題作答格寫入的是 B 組的答案。

### User Story 3 - 把得主答案寫回 Google Sheets 並可還原（Priority: P1）

搶答結束後，老師按「寫回 Google Sheets」，系統把每題最終得主的答案寫入原 Guided Notes 中該題的作答格：作答格原本有子題前綴（如「（1）」）時寫入「前綴＋答案」，否則只寫答案；沒有得主的題目不寫（例外：因判錯而沒有得主的題目，該題作答格恢復為原始值，見 FR-024）。寫入位置只來自 002 匯入時記錄的作答格位置，不寫死任何儲存格；只改作答格的值，其他儲存格、格式與合併都不動。完成後顯示「已寫回 N 格」。若要撤銷，老師按「還原原始內容」，所有作答格恢復成匯入時的原始值。

**Why this priority**：寫回原檔是本系統取代「上台寫黑板」的最終產出（FR-06、§8-9、§8-10），也是 PRD 成功指標「結果回寫」。

**Independent Test**：示範模式匯入範例 A，第 1 題得主答案為「CPU」「作業系統」、第 3 題得主答案為「0」，結束後寫回，檢查示範試算表的 G5、G6、G11 與其他儲存格；再按還原，檢查與原始範本完全相同。

**Acceptance Scenarios**：

1. **Given** 範例 A、已結束，第 1 題（題組，作答格 G5「（1）」、G6「（2）」）得主答案為「CPU」「作業系統」，第 3 題（單題，作答格 G11 無前綴）得主答案為「0」，第 2、4 題無得主，**When** 老師按「寫回 Google Sheets」，**Then** G5 為「（1）CPU」、G6 為「（2）作業系統」、G11 為「0」，其他儲存格（含第 2、4 題作答格）的值、格式與合併皆不變；畫面顯示「已寫回 3 格」。
2. **Given** 範例 B（版面與範例 A 不同），**When** 結束後寫回，**Then** 答案寫入範例 B 匯入時記錄的作答格，不需修改任何設定或程式。
3. **Given** 搶答中或等待開始，**When** 老師（或直接呼叫伺服器）要求寫回，**Then** 系統拒絕並顯示「目前階段不能執行此動作」，試算表完全未被修改；畫面上「寫回 Google Sheets」按鈕在「已結束」以外不可按。
4. **Given** 已結束且所有題目都沒有得主，**When** 老師寫回，**Then** 試算表不變，顯示「已寫回 0 格」。
5. **Given** 已寫回過一次，**When** 老師判錯某題後再寫回，**Then** 該題作答格改為遞補者的答案；若判錯後該題已無得主，該題作答格恢復為匯入時的原始值，並計入「已寫回 N 格」。
6. **Given** 已寫回，**When** 老師在「已結束」或下一輪的「等待開始」按「還原原始內容」，**Then** 所有作答格（含無得主題目）恢復為匯入時的原始值，其他儲存格不變；畫面顯示「已還原 N 格」（N 為作答格總數，範例 A 為 6）。
7. **Given** 搶答中，**When** 要求還原，**Then** 系統拒絕並顯示「目前階段不能執行此動作」。
8. **Given** 試算表未共用給服務帳號，**When** 老師寫回或還原，**Then** 顯示「沒有權限存取試算表，請將試算表共用給服務帳號」，系統內的結果資料不受影響，共用後可再按一次。
9. **Given** Google 服務暫時發生錯誤，**When** 老師寫回或還原，**Then** 顯示「Google Sheets 發生錯誤，請稍後再試」；老師稍後重按即可完成，重複寫回不會產生不同結果。
10. **Given** 試算表已被刪除或找不到，**When** 老師寫回，**Then** 顯示「找不到試算表」。
11. **Given** 寫回進行中，**When** 老師查看畫面，**Then** 寫回、還原按鈕暫時不可按，避免重複送出。

### User Story 4 - 下載 CSV 結果檔（Priority: P2）

搶答結束後，老師按「下載 CSV」取得完整送出紀錄，檔名包含房間碼與第幾輪。每個送出的每個子題一列（含已撤回與判錯），欄位依序為：題號、子題、組別、送出者、答案、伺服器時間（台北時間）、順位、狀態（有效／已撤回／判錯）、是否得主（是／否）。檔案以 Excel 直接開啟時中文正常顯示、特殊字元不錯亂，且答案不會被當成公式執行。

**Why this priority**：CSV 是額外功能（E2），供老師留存與統計；核心流程（結果、判錯、寫回）不依賴它。

**Independent Test**：結束搶答後下載 CSV，以文字檢視確認 BOM、CRLF、表頭、列數與排序，並用含逗號、引號、換行與「=」開頭的答案驗證跳脫與防公式。

**Acceptance Scenarios**：

1. **Given** 已結束，房間碼 K7Q2MX、第 2 輪，**When** 老師按「下載 CSV」，**Then** 下載的檔名包含「K7Q2MX」與輪次 2（例如 `results-K7Q2MX-r2.csv`）。
2. **Given** 已結束，**When** 下載 CSV，**Then** 檔案以 UTF-8 BOM 開頭、每列（含最後一列）以 CRLF 結尾，第一列固定為 `題號,子題,組別,送出者,答案,伺服器時間,順位,狀態,是否得主`。
3. **Given** 第 1 題（2 個子題）有 3 筆送出、第 3 題（單題）有 2 筆送出，**When** 下載 CSV，**Then** 資料列為 3×2＋2×1＝8 列（不含表頭）。
4. **Given** 某送出的伺服器時間為 1970-01-01 00:00:00.000 UTC，**When** 下載 CSV，**Then** 伺服器時間欄為 `1970-01-01T08:00:00.000+08:00`。
5. **Given** 已撤回的送出、被判錯的送出、得主，**When** 下載 CSV，**Then** 狀態分別為「已撤回」「判錯」「有效」；已撤回者順位欄為空、判錯者保留順位；是否得主只有得主那筆為「是」，其餘為「否」。
6. **Given** 答案為 `a,b`、`他說"好"`、含換行的文字，**When** 下載 CSV，**Then** 該欄以雙引號包住、內部雙引號變成兩個雙引號，Excel 開啟後顯示原文。
7. **Given** 答案為 `=1+1`、`+5`、`-3`、`@x`，**When** 下載 CSV，**Then** 該欄輸出為 `'=1+1`、`'+5`、`'-3`、`'@x`，Excel 開啟後不會執行公式。
8. **Given** 送出紀錄順序打亂，**When** 下載 CSV，**Then** 列依「題號升冪 → 順位升冪（無順位者排最後，彼此再依伺服器時間）→ 子題升冪」排序。
9. **Given** 搶答中或等待開始，**When** 老師（或直接呼叫伺服器）要求下載 CSV，**Then** 系統拒絕並顯示「目前階段不能執行此動作」；畫面上「下載 CSV」按鈕在「已結束」以外不可按。
10. **Given** 已結束但沒有任何送出，**When** 下載 CSV，**Then** 檔案只有 BOM 與表頭列。

### Edge Cases

- **沒有得主的題目**：結果表得主與答案顯示「無」；寫回不寫該題作答格（因判錯而無得主者例外，見 FR-024）；CSV 照列該題所有送出（是否得主皆為「否」）。
- **連續判錯到無人可遞補**：每次判錯只影響目前得主；全部判錯後該題沒有得主、分數全部扣回；再按判錯提示「此題目前沒有得主」，不改任何資料。
- **遞補候選中有已撤回者**：已撤回的送出不在順位中，不會被遞補。
- **判錯不可復原**：系統不提供「取消判錯」；被判錯的組不能在本輪重新送出該題。
- **搶答中判錯的資訊隔離**：判錯後各組收到的資料只含本組資訊；被判錯的組只看到「老師判定此答案錯誤」，遞補組與其他組看不到任何變化，直到結束後才在結果中看到。
- **搶答中視窗尚未結算的題目**：沒有得主，判錯提示「此題目前沒有得主」。
- **等待開始時判錯**：拒絕，「目前階段不能執行此動作」。
- **搶答中寫回或下載 CSV**：拒絕，「目前階段不能執行此動作」，試算表不被修改、沒有檔案產生；畫面按鈕不可按。
- **答案含逗號、雙引號、換行或以 = + - @ 開頭**：CSV 依規則跳脫並加單引號；寫回 Google Sheets 時答案以原文字寫入（以純文字值寫入，不會被試算表解讀為公式），不加單引號。
- **答案前後空白**：寫回與 CSV 使用 003 保存的去除前後空白後答案。
- **試算表未共用給服務帳號**：寫回與還原顯示「沒有權限存取試算表，請將試算表共用給服務帳號」；結果資料不受影響，可重試。
- **Google API 暫時錯誤**：顯示「Google Sheets 發生錯誤，請稍後再試」；重試寫回（或還原）為冪等，結果與第一次成功相同。
- **試算表被刪除或網址失效**：顯示「找不到試算表」。
- **老師在試算表中手動改過其他儲存格**：寫回與還原只改作答格，不影響手動修改的非作答格；手動改過的作答格會被寫回值或原始值覆蓋。
- **多次寫回**：每次以當下最終得主重寫；因判錯而沒有得主的題目恢復為原始值；從未有人被判錯的無得主題目不寫，保留試算表上原有的值。
- **判錯到沒有得主、且從未寫回過**：寫回時該題作答格仍寫入原始值（與試算表現有值相同時結果不變），計入 N。
- **重新開始一輪後**：送出、結果與判錯清空；上一輪的寫回仍留在試算表中，可於「等待開始」按「還原原始內容」恢復；CSV 檔名的輪次為新輪次。
- **重新匯入**：「等待開始」重新匯入後，作答格與原始值以新的匯入為準；若重新匯入前已寫回且未還原，新的「原始值」即為當時試算表上的值。
- **題組子題前綴形式**：前綴可能為全形「（1）」或半形「(1)」，寫回時原樣保留匯入時的前綴；作答格原本只有答案或空白時前綴為空，只寫答案。
- **同一題同組多筆送出（撤回後重送）**：CSV 每筆送出各自成列（已撤回者狀態「已撤回」）；結果只顯示未撤回的那筆。
- **新加入或重新整理的學生在已結束階段**：直接看到結果畫面。
- **多個老師分頁**：判錯後所有老師分頁同步更新；寫回、還原、下載 CSV 不改變活動狀態，不推播。

## Requirements *(mandatory)*

### Functional Requirements

**結果顯示（PRD FR-05、FR-09、§8-6）**

- **FR-001**（FR-05）：活動為「搶答中」與「已結束」時，老師畫面 MUST 顯示結果表（搶答中位於即時狀態表下方，見 FR-009）：每題一列（依題號升冪），列出題號、得主組別、得主答案、各組順位。
- **FR-002**（FR-05、E1）：得主答案 MUST 顯示得主送出的答案；題組以子題標籤串接每個子題答案（例如「（1）CPU（2）作業系統」），單題只顯示答案。
- **FR-003**（FR-05）：各組順位 MUST 依順位升冪列出該題所有未撤回的送出（含被判錯者，並標示判錯）；已撤回的送出 MUST NOT 出現。
- **FR-004**（FR-05）：沒有得主的題目，得主與答案欄 MUST 顯示「無」。
- **FR-005**（§8-6）：結果 MUST 顯示各組分數（每題得主 +1，判錯者因不再是得主而 −1），依分數降冪排列，同分依組別順序（第 1 組在前）排列；包含 0 分的組。
- **FR-006**（FR-09）：活動為「已結束」時，學生畫面 MUST 隱藏作答卡，改顯示與老師相同內容的結果（每題得主、答案、各組順位、各組分數），但不含判錯等操作按鈕。
- **FR-007**（FR-09、FR-10）：活動為「已結束」以外的階段，學生收到的資料與畫面 MUST NOT 含任何結果（此限制由 003 保證，本子功能不得破壞）。
- **FR-008**（FR-12）：進入「已結束」後，所有已連線的老師與學生畫面 MUST 在 1 秒內顯示結果；重新整理或之後才連線者 MUST 直接看到結果。

**老師判錯（PRD E5、§5.1-6、§8-6）**

- **FR-009**（E5）：老師畫面 MUST 在「搶答中」與「已結束」顯示結果表（搶答中位於即時狀態表下方），結果表每題提供「判錯」操作（plan D2：沿用 TECH_SPEC §10.4 ResultsTable 的判錯按鈕，不在即時狀態表另設按鈕）。搶答中仍在公平模式視窗、尚未結算（沒有順位）的送出 MUST NOT 列入結果表的順位欄（即時狀態表仍顯示「判定中」）。
- **FR-010**（E5）：判錯 MUST 只在「搶答中」與「已結束」允許；其他階段 MUST 以「目前階段不能執行此動作」拒絕，不論請求是否來自正常畫面。題目不屬於本活動時 MUST 以「找不到此題目」拒絕。
- **FR-011**（E5）：判錯時，系統 MUST 把該題目前得主的送出狀態改為「判錯」；該送出保留原順位但 MUST NOT 再成為得主。
- **FR-012**（E5）：判錯後，系統 MUST 依既有順位由下一個狀態為「有效」且已結算的送出遞補為得主；分數 MUST 隨之重算（原得主組 −1、遞補組 +1）。不得重新排序既有順位。
- **FR-013**（E5）：同一題 MUST 可連續判錯；沒有可遞補者時該題 MUST 沒有得主。
- **FR-014**（E5）：該題目前沒有得主（含無送出、全部已判錯、全部已撤回、公平模式視窗尚未結算）時，判錯 MUST 以「此題目前沒有得主」拒絕，且不改任何資料。
- **FR-015**（E5、§8-3）：被判錯的組 MUST NOT 能在本輪重新送出該題（伺服器以「本組已送出此題」拒絕），也 MUST NOT 能撤回被判錯的送出。
- **FR-016**（E5）：搶答中，被判錯組的學生作答卡 MUST 顯示「老師判定此答案錯誤」、輸入鎖定、不顯示送出與撤回按鈕。
- **FR-017**（FR-10）：搶答中判錯後，每組收到的資料 MUST 仍只含本組資訊；遞補組與其他組 MUST NOT 得知判錯、得主變更、順位或分數。
- **FR-018**（FR-12）：判錯後，老師畫面（含所有老師分頁）與學生畫面（已結束時的結果；搶答中被判錯組的作答卡）MUST 在 1 秒內更新。
- **FR-019**（E3、§8-6）：搶答中判錯後的分數 MUST 立即作為之後公平模式視窗結算的「目前得分」。
- **FR-020**：判錯 MUST 不可復原；判錯紀錄只在「重新開始一輪」時隨送出一併清除。
- **FR-021**（E5）：判錯與遞補 MUST 在伺服器的單一交易內完成，並發的多次判錯不得造成同一題兩位得主或跳過候選。

**寫回 Google Sheets（PRD FR-06、§8-9、§8-10）**

- **FR-022**（FR-06）：老師 MUST 能在「已結束」按「寫回 Google Sheets」；其他階段 MUST 以「目前階段不能執行此動作」拒絕且 MUST NOT 修改試算表；畫面上的按鈕在「已結束」以外 MUST 不可按。
- **FR-023**（FR-06、§8-9）：寫回 MUST 對每題目前的最終得主，將其每個子題答案寫入該題對應子題的作答格；作答格有子題前綴時寫入值 MUST 為「前綴＋答案」，否則 MUST 為答案本身。
- **FR-024**（§8-9、E5）：沒有得主、且沒有任何被判錯送出的題目 MUST NOT 產生任何寫入。沒有得主、但有被判錯送出的題目（判錯到無人可遞補），寫回時 MUST 把該題每個作答格寫為匯入時的原始值，使試算表不殘留被判錯的答案。
- **FR-025**（FR-06、憲章原則 V）：寫入位置 MUST 只來自 002 匯入時記錄的作答格位置（工作表與儲存格）；MUST NOT 使用任何寫死的儲存格位址。換用版面不同的範本時 MUST 不需修改程式或設定。
- **FR-026**（FR-06）：寫回與還原 MUST 只改作答格的值；MUST NOT 修改其他儲存格的值，也 MUST NOT 修改任何儲存格的格式或合併。
- **FR-027**（FR-06）：寫入值 MUST 以純文字寫入，不被試算表解讀為公式或自動轉換格式。
- **FR-028**：寫回完成後，老師畫面 MUST 顯示「已寫回 N 格」，N 為本次寫入的作答格數（含 FR-024 恢復原始值的格；可為 0）。
- **FR-029**（§8-10）：老師 MUST 能在「等待開始」或「已結束」按「還原原始內容」，把所有作答格（不論有無得主）恢復為匯入時記錄的原始值；完成後 MUST 在與「已寫回 N 格」相同位置顯示「已還原 N 格」，N 為本次寫入的作答格總數。「搶答中」MUST 以「目前階段不能執行此動作」拒絕。
- **FR-030**：寫回、還原失敗時 MUST 依原因顯示：沒有權限 →「沒有權限存取試算表，請將試算表共用給服務帳號」；找不到試算表 →「找不到試算表」；其他 Google 錯誤 →「Google Sheets 發生錯誤，請稍後再試」。失敗 MUST NOT 影響系統內的結果、分數與活動階段，老師 MUST 可重試。
- **FR-031**：重複執行寫回（或還原）MUST 產生相同的試算表結果（冪等）。
- **FR-032**：寫回或還原進行中，老師畫面 MUST 暫時停用寫回、還原按鈕，避免重複送出。
- **FR-033**：寫回、還原 MUST NOT 改變活動階段、結果或分數，也 MUST NOT 推播給學生。
- **FR-034**（憲章原則 X）：在示範（fake）模式下，寫回與還原 MUST 作用於示範用試算表副本，並可供驗證寫入結果；行為與真實 Google Sheets 一致。

**CSV 匯出（PRD E2）**

- **FR-035**（E2）：老師 MUST 能在「已結束」下載 CSV；其他階段 MUST 以「目前階段不能執行此動作」拒絕；畫面上的按鈕在「已結束」以外 MUST 不可按。
- **FR-036**（E2）：CSV 檔名 MUST 包含房間碼與輪次（格式 `results-<房間碼>-r<輪次>.csv`）。
- **FR-037**（E2）：CSV MUST 以 UTF-8 BOM 開頭，每列（含最後一列）以 CRLF 結尾；第一列 MUST 為 `題號,子題,組別,送出者,答案,伺服器時間,順位,狀態,是否得主`。
- **FR-038**（E2、E1）：CSV MUST 為每個送出（含已撤回與判錯）的每個子題各輸出一列；單題的子題欄為 1。
- **FR-039**（E2）：欄位內容：組別為組名（如「第 1 組」）；送出者為送出成員暱稱；答案為該子題去除前後空白後的答案；伺服器時間 MUST 為台北時間 `YYYY-MM-DDTHH:mm:ss.SSS+08:00`；順位為該送出的順位，已撤回者為空；狀態為「有效」「已撤回」「判錯」；是否得主為「是」或「否」。
- **FR-040**（E2）：任一欄位含逗號、雙引號、CR 或 LF 時 MUST 以雙引號包住，內部雙引號 MUST 變成兩個雙引號。
- **FR-041**（E2）：任一欄位以 `=`、`+`、`-`、`@` 開頭時 MUST 在前面加單引號 `'`，避免被試算表軟體當成公式。
- **FR-042**（E2）：CSV 列 MUST 依「題號升冪 → 順位升冪（無順位者排最後，彼此再依伺服器時間升冪）→ 子題升冪」排序。
- **FR-043**：CSV 內容 MUST 反映下載當下的最終狀態（含所有已完成的判錯）。

### Key Entities *(include if feature involves data)*

- **送出（Submission）**：沿用 003；本子功能新增使用「判錯」狀態。判錯的送出保留名次但不能是得主，被判錯的組不能再送出該題。
- **作答格（AnswerSlot）**：沿用 002；每題每子題一格，記錄工作表名稱、儲存格位置、子題前綴、匯入時原始值；是寫回與還原唯一的位置與原始值來源。
- **結果（Results）**：由送出紀錄推導、只在「已結束」提供給學生；含每題（題號、是否題組、子題標籤、得主組別／答案／送出者或無得主、未撤回送出的順位清單——每筆含順位、組別、答案、送出者、伺服器時間、狀態有效或判錯、是否得主）與各組分數（降冪、組序升冪）。
- **儲存格寫入（CellWrite）**：一次寫回或還原中的一筆寫入，含工作表名稱、儲存格位置、寫入值；寫回時寫入值＝前綴＋得主答案，還原時＝原始值。
- **CSV 列（CsvRow）**：一個送出的一個子題；含題號、子題、組別名稱、送出者、答案、伺服器時間、順位（可空）、狀態、是否得主。
- **試算表閘道（Sheets Gateway）**：系統與 Google Sheets（或示範用試算表副本）之間的介面；本子功能使用其「寫入儲存格」能力，並把權限不足、找不到、其他錯誤分別回報。
- **活動（Session）**：沿用 001；本子功能使用其階段、房間碼、輪次、試算表識別。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：以兩份版面不同的範例範本各完成一輪並寫回，100% 的得主答案出現在正確作答格（含正確前綴），其他儲存格的值、格式與合併 0 處改變。
- **SC-002**：寫回後按「還原原始內容」，試算表與匯入前完全相同（0 處差異）。
- **SC-003**：老師按「結束搶答」或「判錯」後，所有已連線的老師與學生畫面在 1 秒內顯示最新結果（本機）。
- **SC-004**：判錯驗收範例（A 得主被判錯 → B 遞補、A −1／B +1；連續判錯到無人可遞補；無得主再判錯；等待開始判錯）100% 得到規格所述結果，且每題得主數始終 ≤ 1。
- **SC-005**：下載的 CSV 以 Excel 直接開啟，中文 0 處亂碼；含逗號、雙引號、換行的答案 100% 顯示原文；以 `=`、`+`、`-`、`@` 開頭的答案 0 個被當成公式執行。
- **SC-006**：CSV 資料列數 100% 等於所有送出的子題總數，排序 100% 符合「題號 → 順位（無順位最後）→ 子題」。
- **SC-007**：在「已結束」以外要求寫回或下載 CSV、在「等待開始」要求判錯、在「搶答中」要求還原，100% 被拒絕且試算表與資料 0 處改變。
- **SC-008**：搶答中判錯後，任一非被判錯組收到的資料中，判錯、得主、順位、分數資訊出現次數為 0。
- **SC-009**：試算表未共用時，老師 100% 看到「沒有權限存取試算表，請將試算表共用給服務帳號」；共用後重試一次即成功。
- **SC-010**：示範模式下，從按「寫回 Google Sheets」到顯示「已寫回 N 格」< 2 秒（本機）。

## Assumptions

- 組別名稱一律為「第 N 組」（數字前後各一個空白，沿用 001 的組名規則）；本文件範例中的組名皆依此格式。
- Clarifications Q1（FR-024）、plan D2（FR-009）與 Q3（「已還原 N 格」）需先同步 `docs/PRD.md` §8-9、`docs/TECH_SPEC.md` §7.9、§10.4、§12.6 與 `docs/TEST_SPEC.md`（新增 UT-SVC-REJ-07、UT-UI-EXP-02）後才能實作（憲章原則 II；同步內容見 plan.md「實作前置閘門」）。

- 寫回只寫到 002 匯入的那份試算表與工作表；不支援改寫到其他檔案。
