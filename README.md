# 課堂分組搶答系統

> 本檔為最小版本（004 T019 建立）；001～003 的功能說明由各子功能補充。

## 功能清單

- **老師登入／登出**：輸入管理密碼（`.env` 的 `TEACHER_PASSWORD`）進入管理頁；同一分頁重新整理維持登入，新開分頁需重新登入。按「登出」清除本分頁的老師身分並回到登入頁。
- **建立活動**：產生 6 碼房間碼（大寫英文與數字，不含 I、O、0、1）；預設 6 組、判定模式「公平」、視窗 3 秒、階段「準備中」。管理頁顯示目前活動，已有活動時不再顯示建立入口。
- **活動設定**：準備中或等待開始時可調整組數（2–20）、判定模式（公平／純速度）與視窗秒數（1–10，只在公平模式顯示）；要移除的組別已有成員時拒絕變更。
- **學生加入**：以房間碼（不分大小寫，可由 `/join?room=<房間碼>` 連結預填）查詢各組與人數，選組並輸入暱稱（1–20 個中文字、英文字母或數字，同組不可重複）後進入作答頁，顯示組名、暱稱、本組組員與目前階段。
- **即時名單**：老師即時看到每組成員、人數與上線狀態（至少一個分頁連線中即為上線）；學生只收到本組的成員資料。
- **重連**：學生重新整理或斷線恢復後自動回到原組別與暱稱，不建立新成員；已加入者再開加入頁直接回到作答頁；身分失效時導回加入頁並帶入原房間碼。伺服器重新啟動後所有成員先顯示離線，重新連線後恢復上線。
- **匯入 Guided Notes**：準備中或等待開始時，老師貼上 Google 試算表網址或 ID 後按「匯入」，系統依「題號／作答」表頭辨識題目與題組（格式見下方「Guided Notes 範本格式」），只記錄題號與作答格位置，不顯示、不傳送題目敘述。成功後顯示「偵測到 N 題，其中 M 題組（共 K 子題）、L 單題」與題號清單，活動進入「等待開始」；題號不連續時仍匯入並顯示警告，題號重複、找不到表頭、網址格式錯誤或無權限時顯示原因且不影響原有題目。等待開始時可重新匯入，新題目取代舊題目並即時推送給學生；重新整理管理頁後摘要仍在。示範模式（`SHEETS_MODE=fake`）可輸入範例 ID `fixture-template-a`（4 題、2 題組）或 `fixture-template-b`（6 題、0 題組）。
- **開始／結束／重新開始一輪**：等待開始且已匯入題目時，老師按「開始搶答」進入搶答中；搶答中按「結束搶答」會先立即結算仍在判定中的題目再進入已結束；已結束時按「重新開始一輪」清除所有送出與草稿，保留題目、組別、成員與設定，回到等待開始（輪次加 1）。控制列依階段只有對應的一顆按鈕可按，按下即執行；所有老師與學生畫面在 1 秒內顯示新階段。搶答中以外的階段，學生的輸入框與送出按鈕鎖定（提示「等待老師開始」），伺服器也拒絕此時的草稿、送出與撤回。
- **作答與即時狀態表**：學生每題一張作答卡，題組依子題顯示多個輸入框（「（1）」「（2）」），任一子題空白時不能送出；同組任一成員送出即代表全組送出，每組每題只能有 1 筆有效送出，送出後鎖定並顯示「已送出 HH:mm:ss」。送出時間與名次一律以伺服器時間決定，任何並行情況下每題最多 1 位得主。老師以「題號 × 組別」表格即時看到每組的答案、送出者、伺服器時間（精確到毫秒）、順位與「★ 得主」，送出後 500 毫秒內更新。搶答結束前，學生只看得到本組的成員、草稿與送出，看不到他組是否送出、答案、順位、得主或分數。
- **組內共編草稿**：搶答中同組成員看到同一份草稿，任一人輸入後 1 秒內同步給組員；草稿只傳給本組，不傳給其他組或老師。以整題為單位保存，最後收到的更新為準（同時編輯同一題不同子題時，後到的更新可能覆蓋尚未同步的內容）。
- **純速度與公平模式**：純速度模式下每題第一個有效送出立即成為得主。公平模式下某題收到第一筆送出時開啟 W 秒視窗（活動設定的視窗秒數，1–10，預設 3），老師的題目欄顯示「判定中 x.x s」倒數；到期時視窗內的送出依「目前得分少者優先 → 送出時間較早 → 處理順序」排序，第一名為得主。題目結算後其他組仍可送出，作為遞補候選。每題得主所屬組 +1 分。
- **撤回**：送出後 10 秒內，同組成員可按「撤回（n 秒）」撤回本組的送出；撤回後作答卡恢復可編輯並帶入原答案，老師的格子顯示「已撤回」。撤回的若是得主，由下一筆有效送出遞補；公平模式下視窗中的題目因撤回而沒有候選時回到未作答。重新送出視為新的送出，以新的伺服器時間計算。
- **斷線重連與重啟恢復**：學生重新整理或斷線重連後立即收到最新狀態，包含本組草稿、送出狀態與撤回剩餘時間（依原送出時間計算，不重新計時）。伺服器重新啟動後恢復所有活動、送出與草稿；判定中的題目已過到期時間者立即結算，未到期者依原到期時間繼續判定。
- **結果畫面（老師／學生）**：搶答結束後，老師看到結果表（每題得主組別、得主答案、各組順位，含被判錯、不含已撤回的送出）與各組分數（分數高到低，同分依組別順序）；沒有得主的題目顯示「無」。學生在結束後看到相同內容（含各組分數），結束前看不到。
- **老師判錯與遞補**：搶答中或結束後，老師可對某題按「判錯」——原得主扣回 1 分，依既有順位由下一個有效送出遞補並得 1 分；可連續判錯，無人可遞補時提示「此題目前沒有得主」。被判錯的組不能重送該題，畫面顯示「老師判定此答案錯誤」。
- **寫回 Google Sheets**：已結束時可把每題最終得主的答案寫回原 Guided Notes 的作答格（作答格有子題前綴如「（1）」時寫入「前綴＋答案」）。只改作答格的值，不改其他儲存格、格式與合併；寫入位置一律來自匯入時記錄的位置。完成後顯示「已寫回 N 格」。
  - 因判錯而沒有得主的題目（得主被判錯且無人遞補）：寫回時該題作答格恢復為匯入時的原始值，並計入「已寫回 N 格」；從未被判錯、本來就沒有得主的題目不寫。
- **還原原始內容**：等待開始或已結束時，把所有作答格恢復成匯入時的原始值，完成後顯示「已還原 N 格」。
- **下載 CSV**：已結束時下載 `results-<房間碼>-r<輪次>.csv`，每個送出的每個子題一列（題號、子題、組別、送出者、答案、伺服器時間〔台北時間〕、順位、狀態、是否得主）。UTF-8 含 BOM、CRLF 換行，Excel 可直接開啟；以 `=`、`+`、`-`、`@` 開頭的答案前面加 `'`，避免被當成公式。

## Guided Notes 範本格式

匯入不限定特定檔案；助教用其他 Guided Notes 測試時，只要保留以下「題號／作答」表頭結構即可（PRD §9）：

- **表頭**：任一工作表中，同一列要同時有「題號」與「作答」兩個儲存格（合併儲存格以左上角為準）；兩者所在欄即題號欄與作答欄。
- **題號**：表頭以下，題號欄填整數，例如 `1`、`2`、`3`；也接受 `1.0`、前面補零的 `01` 與前後空白。題號欄空白的列（間隔列）會被忽略。題號不從 1 開始或有缺號時仍可匯入，但會顯示警告；題號重複時拒絕匯入。
- **題組**：把題號儲存格**向下縱向合併** n 列（n > 1），這 n 列就是該題組的子題；沒有合併的題號為單題。
- **子題編號**：子題的作答格可用「（1）」「（2）」（或半形 `(1)`）開頭標示；沒有標示時依列序編為 1..n。寫回時會保留這個前綴。
- **範例**：`fixtures/sheets/template-a.xlsx`（範例 A，含題組）、`fixtures/sheets/template-b.xlsx`（範例 B，皆為單題）；示範模式下以範例 ID `fixture-template-a`、`fixture-template-b` 匯入。

## Google Sheets 服務帳號設定（`SHEETS_MODE=google`）

1. 在 Google Cloud Console 建立（或選擇）專案，**啟用 Google Sheets API**。
2. 在該專案建立**服務帳號**，為它新增 JSON 金鑰並下載。
3. 把金鑰檔放到 `secrets/service-account.json`。`secrets/` 已列在 `.gitignore`，**金鑰不得提交**到版本庫。
4. 在根目錄 `.env` 設定：

   ```sh
   SHEETS_MODE=google
   GOOGLE_APPLICATION_CREDENTIALS=./secrets/service-account.json
   ```

5. 打開要匯入的試算表，按「共用」，把試算表共用給服務帳號的 email（金鑰檔中的 `client_email`，形如 `xxx@<專案>.iam.gserviceaccount.com`），權限設為「編輯者」（寫回與還原需要編輯權限）。
6. 重新啟動伺服器後，在管理頁貼上試算表網址即可匯入。

## 如何執行

需要 Node.js 22.13 以上。

```sh
npm install
cp .env.example .env    # 設定 TEACHER_PASSWORD；SHEETS_MODE 預設 fake
npm run dev             # 伺服器與前端
npm test                # 單元與整合測試
npm run lint
```

### 示範模式（`SHEETS_MODE=fake`）

- 匯入時輸入範例 ID：`fixture-template-a`（範例 A）或 `fixture-template-b`（範例 B），資料來自 `fixtures/sheets/`。
- 寫回與還原只改記憶體中的副本，並輸出到 `data/fake-sheets/<試算表 ID>.json`（例：`data/fake-sheets/fixture-template-a.json`）。
- 也可用 `GET /api/dev/fake-sheets/<試算表 ID>` 查看目前內容，`POST /api/dev/fake-sheets/<試算表 ID>/reset` 恢復成 fixture。

### Google 模式（`SHEETS_MODE=google`）

1. 服務帳號金鑰放在 `secrets/`（不得提交），並在 `.env` 設定 `GOOGLE_APPLICATION_CREDENTIALS`。
2. 把要使用的試算表**共用給服務帳號（編輯者）**——寫回與還原需要編輯權限。
3. 若出現「沒有權限存取試算表，請將試算表共用給服務帳號」，請確認第 2 步的共用對象與權限後再試一次。
